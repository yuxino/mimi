# 死代码清理

## 适用时机

- 用户明确要求清理死代码/垃圾代码/无效代码。
- 完成功能改动后,顺手清理由该改动遗留的死代码(例如删除某个开关后,它专属的图标、文案键、工具函数不再被引用)。
- 重构或删除功能时,检查并移除连带失效的代码。

## 清理对象(按常见度排序)

1. **未使用的 import**——删除后 TypeScript 编译会报,也可用 eslint 检测。
2. **未使用的变量/常量/函数/组件**——特别是模块级导出的常量,先全局搜索确认无引用。
3. **未使用的 props / 参数**——组件 props 中不再使用的字段。
4. **无引用的图标/图标名**——删除某功能后 Icon.tsx 里的图标条目(import + 类型 + 映射表三处都要删,漏一处会编译失败)。
5. **无引用的 i18n 文案键**——删除功能后 i18n.ts 里的键;注意检查 zh/en(以及其他语言)所有组都要删,且确认没有其他文件引用。
6. **无引用的类型/接口/枚举成员**。
7. **被注释掉的整段代码**。
8. **无效分支**——如恒 false 的条件、永远 return 的代码。

## 工作流

1. **先搜索再删**:对每个疑似死代码,用 `grep` 全局搜索引用(包括 `.ts`、`.tsx`、`.rs`、`.mjs`、配置文件),确认无引用才删。注意区分"定义处"和"使用处"。
2. **连带清理**:删除一个功能时,把它专属的辅助函数、常量、类型、图标、文案一起删,不要只删调用点。
3. **检查交叉文件**:i18n 键可能在 types.ts 或 E2E 脚本里被引用;Icon 名可能在多个窗口用;Rust 端删功能时检查 commands.rs / session_manager.rs 等。
4. **删完必验**:删除后运行 `npm run build`(tsc 会抓未用 import 和缺失引用)+ `npm run lint` + `npm run test`;改动 Rust 则跑 `./scripts/check.sh`。
5. **注意导出的公共 API**:`lib/types.ts`、`lib/ipc.ts` 里的导出可能被多个窗口共享,删之前务必全局搜。

## 反例(不要删)

- 测试里引用的符号(如 segmenter 的函数、测试数据)。
- 配置/构建脚本里引用的路径或脚本。
- 对外部有约定意义的字符串(如 wire protocol 的 JSON 键、E2E 断言文本、localStorage 键)。
- 语义上是"未来扩展点"但注释明确说明用途的代码——拿不准时问用户。

## 完成标准

- `git diff --stat` 只包含预期删除 + 必要的连带修改。
- `npm run build`、`npm run lint`、`npm run test` 全绿;Rust 改动跑 `./scripts/check.sh`。
- 不留半删状态(例如只删了调用点、没删定义)。
