## English

### What's changed

- Use one fixed self-signed certificate for macOS releases instead of a new ad-hoc identity on every build. Development builds also retain their fixed identity and separate app identifier.
- Reject missing, ad-hoc, or unexpected release identities. Verify the app inside the DMG, its signed source revision, and the updater archive before publication.
- Add recording-permission recovery steps and clarify that stable self-signing does not require a paid Apple Developer membership.

### Updating and verification

Update in **Settings → General → Software Update**, or download the installer below. Keep the macOS app at `/Applications/mimi.app`.

**One-time migration:** v1.4.1 and earlier public macOS builds used an ad-hoc identity. The first update to this fixed identity may require a new **Screen & System Audio Recording** grant. If capture stays denied despite an enabled switch, quit Mimi, remove only its old recording-permission entry, add `/Applications/mimi.app` again, enable permission, and reopen it. Do not delete certificates or saved API keys.

This removes build-specific recording identity changes; it does not promise that macOS will never request consent again. Self-signing does not guarantee password-free Keychain access across updates. The app is not Apple-notarized, so Gatekeeper may require **Open Anyway**. Windows installers are not Authenticode-signed, so SmartScreen may warn. The existing updater verification key is unchanged.

Validation covers the Rust/frontend checks, signing and archive regression tests, a real fixed-signed app and matching DMG, and unchanged designated requirements after signed content changes. The development bundle's fixed identity was verified; its UI launch was not completed because the formal app was running. Real recording across an installed update and Windows device interaction remain unverified.

## 中文

### 本次修复

- macOS 正式版沿用同一张固定自签名证书，修复每次构建使用临时身份的问题。开发测试版也继续使用固定身份和独立应用标识。
- 缺少证书、临时签名或正式版身份不匹配时直接拒绝发布；发布前核对 DMG 内应用、签名保护的源码版本和更新包。
- 补充录音权限失效时的处理步骤，并明确固定自签名不需要付费 Apple 开发者会员。

### 更新与验证说明

在「**设置 → 通用 → 软件更新**」中更新，或下载下方安装包。macOS 正式版请保留在 `/Applications/mimi.app`。

**一次性迁移：**v1.4.1 及更早的 macOS 公开版本使用临时身份。首次升级到固定身份时，可能需要重新授予一次「**屏幕与系统音频录制**」权限。若开关已开启但仍提示拒绝采集，请退出 Mimi，仅移除旧的 Mimi 录音权限条目，重新添加 `/Applications/mimi.app`、开启权限并重新打开。不要删除证书或已保存的 API Key。

本次消除了每次构建更换录音身份的原因，不代表 macOS 永远不会再询问授权。自签名无法保证更新后钥匙串完全不再询问密码。应用尚未经过 Apple 公证，Gatekeeper 可能需要选择「仍要打开」。Windows 安装包未做 Authenticode 签名，SmartScreen 可能提示警告。自动更新的验证公钥保持不变。

验证包括 Rust／前端检查、签名与归档回归测试、真实固定签名应用及一致的 DMG，以及修改签名内容后完整签名要求仍保持不变。开发版固定身份已经核对；由于正式版仍在运行，未完成开发版界面启动验证。跨已安装版本更新的真实录音，以及 Windows 实机交互仍未验证。

**完整更新记录**：https://github.com/yuxino/mimi/compare/v1.4.1...v1.4.2
